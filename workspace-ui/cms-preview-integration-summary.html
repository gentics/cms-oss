CMS Preview in the Workspace: Summary

As of 2026-10-08 · Short version of the spike

Yes, the CMS page can be shown and clicked inside the Workspace. Showing it works with the CMS as it is. Selecting and editing single elements needs one change from GenAIx: it must accept a reference to one element.

How it would work

  1. Show the page. The Workspace builds the link to the page itself and shows it in a frame, read-only. The Workspace runs on the same server as the CMS, so it can look into the frame.
  2. Find the elements. The Workspace looks for the CMS's markers on each element (headline, image, text block…).
  3. Select an element. The Workspace draws outlines in its own layer on top of the page. The customer's page itself is never changed.
  4. Edit it. The user asks the AI (or types the text by hand), and GenAIx writes the change to the CMS. The frame then reloads and highlights what changed.

Edit a text with GenAIx

  1. Click the element in the page.
  2. Write in the chat what should change, e.g. "Make the headline shorter".
  3. GenAIx makes the change. It may ask a question back first.
  4. The change is saved right away (not published), the page reloads and the changed element is highlighted.
  5. Not happy? Ask again or edit it yourself. Done? Press Publish.

Until GenAIx can receive "this element", the user names the element in words instead of clicking it.

Editing text yourself

Besides asking the AI, the user can switch to "Edit by hand": the page opens in the CMS's own edit mode, the user types directly in the page and clicks Apply or Cancel, and the page goes back to read-only. It is only offered while the AI is not working, so the two never write at the same time.

  • Good: typing directly in the page with Cancel / Apply, like in the mockup; a "written by hand" note in the chat; uses the CMS's proven editing.
  • Effort: medium. The Workspace needs a small connection to the CMS's edit mode and draws the editing toolbar itself. Full CMS editing (tags, images, files) would be large.
  • Toolbar in our design: the CMS hands the toolbar buttons to the Workspace, so it can look like the mockup.
  • Watch out: the page is locked while editing; GenAIx does not know about the hand edit unless we tell it; the outlines are probably only shown outside edit mode.
  • Cheap fallback: an "Open in CMS editor" button that opens the page in the existing CMS editor in a new tab.

Plan: start with a small form for hand edits plus "Open in CMS editor", and add "Edit by hand" when users need it.

When changes are saved

Right away. Every change GenAIx makes is saved in the CMS immediately, as an unpublished version. There is no extra "save" step. Nothing goes live until someone presses Publish.

  • Publish works: it publishes the page, or sends it for review if the user may not publish.
  • Save has nothing left to save. It could instead mean "stop the AI and freeze the session".
  • Discard is unclear: GenAIx has a discard action, but nothing says it undoes the changes in the CMS. We need to ask GenAIx.

If we can change the CMS

The Workspace lives in the CMS repository. If we may adapt the CMS for it, four things get easier. Everything else stays the same, including the GenAIx blocker.

  • Element markers: we add a read-only mode with markers ourselves, instead of relying on a setting.
  • Lock extras: "from the data source", "ask for the lock" and "leave a note" can be built.
  • Discard: we can go back to the page version from before the session.
  • "Edit by hand": the same medium effort, but easier to adjust.

What we need

  1. From GenAIx: accept a reference to one element on a page. This is the only blocker.
  2. From GenAIx: say what "Discard" does to the CMS.
  3. From the team: decide whether we may change the CMS for the Workspace.

Differences from the mockup

  • The page is the real website, not a demo page. Only outlines, labels and menus come from the Workspace.
  • Locks are per page, not per element. "M. Weber is editing this quote" becomes "M. Weber is editing this page".
  • Hand edits start in a small form; typing directly into the page comes with "Edit by hand", a medium effort with the toolbar in our design.
  • "Accept / Discard" per suggestion has no counterpart in GenAIx yet. Product needs to decide.
  • Everything else carries over: desktop/mobile/full screen, outlines, highlights, focus mode, page tabs.

Decisions for the team

  • May we change the CMS for the Workspace?
  • May the Workspace save page changes itself, or only through GenAIx?
  • Is it acceptable that the customer's page scripts run in the same context as the Workspace?
  • Does our production setup add security headers that block the frame?

Next step

A one-day prototype against a real CMS: build the link from a real GenAIx update, show the page read-only, check that it stays unlocked, look for the element markers with the setting off and on, and draw outlines on top.
